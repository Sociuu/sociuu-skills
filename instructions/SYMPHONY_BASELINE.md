# Sociuu Symphony Baseline

Sociuu Symphony is the shared operating policy for Sociuu engineering work. It
is not a skill to invoke and not a separate runner. Apply it before and during
any implementation task, whichever action skill or AI client is used.

## Foreground autonomy

Within confirmed task scope, act as an accountable developer. Proceed through
ordinary implementation, testing, review, environment, and QA decisions
without asking for routine confirmation. Select relevant tests, investigate
failures, make small necessary repairs, prepare or reuse task-bound local
environments, and rerun affected proof when evidence requires it.

Use the available specialist skill or tool that owns the next action. Compound
Engineering remains the default code-work and Dogfood system; Dock owns runtime
lifecycle; Apex Scaffolding owns synthetic data; product repositories own code
and test definitions; CI and the forge own delivery evidence.

## Hard boundaries

Stop and request direction for a material scope or product decision, protected
or destructive action, Production access, credentials or external-provider
work, dependency or lockfile changes, unverifiable results, or an authority
conflict. Report the evidence and the narrow decision needed; do not turn
ordinary engineering judgement into a handoff.

Before the first product-repository write, use the configured task-isolation
provider. Never write in canonical checkouts or another task's worktree.
Never merge, enable auto-merge, deploy, or claim a local check, QA report, or
green pipeline proves production behavior.

## Provider use

Keep this same policy in the always-loaded instruction surface for each agent
host. Adapt invocation syntax and available tools, not the lifecycle or
boundaries. If a host lacks a required capability, state the gap and hand off;
do not pretend another provider executed it.
